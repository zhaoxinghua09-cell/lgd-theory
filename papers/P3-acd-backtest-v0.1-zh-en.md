## 摘要（Abstract）

**中文**。算法变更分级判定（Algorithm Change Determination, ACD）能否被一套结构化方法稳定复现，是 AI 医疗器械上市后治理可判定性的一个具体落点。本文给出 ACD 判定器的真实实现与设计（基于可追源文件的确定性规则引擎），并给出一套尚未执行的回测实验方案。本文**如实报告**：方法层资产真实存在且可复现，但实证层（真实判例样本 + 一致性度量）当前为空，故本稿不构成回测结论，仅作为后续补实验的基线工作稿。

**English**. Whether Algorithm Change Determination (ACD) can be reproduced stably by a structured method is a concrete instantiation of post-market governability for AI-enabled medical devices. This paper reports the *actual* implementation and design of an ACD judge (a deterministic rule engine traceable to source files) and presents a backtest protocol that has *not yet been executed*. We report honestly: the method-level assets are real and reproducible, but the empirical layer (real case judgments + agreement metrics) is currently empty. This draft therefore establishes no backtest conclusion and serves only as a baseline for future experiments.

**关键词**：算法变更分级；预定变更控制；AI 医疗器械；判定可复现性；回测
**Keywords**: algorithm change determination; PCCP; AI-enabled medical device; determinability; backtest

## §1 研究问题（Research Question）

人工智能医疗器械上市后算法变更频繁，而"某次变更是否需要重新申报"的判定标准跨辖区不一致，企业在重大/中等/轻微之间缺乏可依赖的前置判定方法。本研究提出并检验一个操作性研究问题：

> **RQ**：给定一段结构化的变更描述（变更类型集合 + 目标监管市场 + 是否在已批准的预定变更控制计划内），ACD 判定器能否产出**稳定、可复核、与独立专家判定一致**的风险档位与建议注册路径？

该问题拆为三个可证伪子问题：

- **RQ1（内部可复现性）**：同一输入是否必然得到同一输出？（判定器为确定性规则引擎时，理论上应为 100%。）
- **RQ2（人机一致性）**：判定器输出与 ≥2 名独立合规/注册专家的盲法判定，在风险档位上的一致性如何？（以 Cohen's Kappa、一致率、分歧归因度量。）
- **RQ3（跨市场稳定性）**：同一变更描述在 NMPA / FDA / EU MDR / PMDA 四类市场下的路径建议差异，是否可由明确规则解释而非随机漂移？

> 截至 v0.1，**RQ1–RQ3 均未被实证检验**。本稿仅定义问题与协议。

## §2 方法：ACD 判定器设计（基于真实实现，Method as Implemented）

本节内容**全部**可追至 `acd-md-judge/index.html`（ACD 判定器 v0.2，规则库版本 `v0.2 (2026-09-23, 按独立合规审查意见修订)`）。该实现是一个**客户端确定性规则引擎**：无模型推理，纯规则查表 + 取最高风险项 + 计划内降档。这与"规则引擎而非模型推理"的方向一致（相关外部讨论亦指出，确定性计算不宜交给模型推理）。

### 2.1 输入空间（Inputs）

| 输入维度 | 取值 | 来源 |
|---|---|---|
| 目标监管市场 | NMPA / FDA / EU MDR-AI Act / PMDA（4 类） | `index.html` `market` 下拉 + `PATHS` |
| 变更类型（可多选） | 14 类（见 §2.2） | `index.html` `RULES` |
| 预定变更控制状态 | 是否在已获批 PCCP / PACMP / DMPA 范围内（布尔） | `index.html` `pccp` 勾选 |

### 2.2 默认风险档映射（14 类变更 × 3 档，Default Risk Map）

下表为判定器内置的默认档位（依据状态：`已核实`=文件名经独立合规审查核实；`待核实`=文件名/条款号/日期待查原文）。**该表是真实实现，非设计提案。**

| # | 变更类型（实现内键名） | 默认风险档 | 依据状态 |
|---|---|---|---|
| 1 | 模型架构 / 权重结构变更 | 高 | 待核实 |
| 2 | 数据分布 / 人群漂移 | 高 | 待核实 |
| 3 | 同分布数据再训练（超参不变） | 中 | 已核实 |
| 4 | 训练数据集重大扩充 | 高 | 待核实 |
| 5 | 算法锁定状态改变（锁定→自适应） | 高 | 待核实 |
| 6 | 生成式大模型组件替换 | 高 | 待核实 |
| 7 | 第三方基础模型版本升级 | 高 | 待核实 |
| 8 | 预期用途扩展 | 高 | 已核实 |
| 9 | 输入 / 输出接口变更 | 高 | 已核实 |
| 10 | 性能 / 告警阈值调整（收紧） | 中 | 待核实 |

| 13 | 人机界面变更（非关键任务） | 低 | 待核实 |

> 注：方法初稿（见来源文件 `框1_人工智能医疗器械算法变更分级判定方法_初稿.md`）为 **8 类 × 3 档**；判定器实现已扩展为 **14 类**（新增：训练数据重大扩充、锁定状态改变、生成式组件替换、第三方模型升级、阈值放宽、关键任务界面、接口变更升档等）。两版映射差异本身即一项待核验的方法演进记录。

### 2.3 三条判定规则（Realized in `run()`）

1. **就高原则（保守口径）**：`overall = max(risk over selected types)`。多项变更时取最高风险项，并提示 RA 逐项复核组合效应。
2. **计划内降档原则**：若勾选"在已获批预定变更控制计划内"，且不含高风险项，则判定降至「轻微」（按修改协议执行 + 记录）；高风险项**不**因计划内而降档。
3. **用途不可覆盖原则**：预期用途扩展为高风险，且 PCCP 不覆盖预期用途变更——即使勾选计划内，高风险结论仍成立（FDA 口径明确；NMPA 无官方 PCCP 制度，正式结论一律按变更注册评估）。

### 2.4 输出与强制门控（Output & Mandatory Gate）

输出包含：风险档位（重大/中等/轻微）、按市场给出的建议路径、逐变更项风险胶囊与动作、依据文本、依据登记表（9 项文件 + 已核实/待核实标记）。

**强制门控**（实现内固定文案）：本结果为 AI 辅助初筛草稿，逐条判定须 RA 人工确认后方可进入任何正式文件；不替代 NMPA/FDA 审评。

### 2.5 依据登记表与审查状态（Basis Register）

判定器内置 9 项依据文件，`已核实` 与 `待核实` 混合：已核实项含《医疗器械监督管理条例》（国务院令 739 号）、《医疗器械注册与备案管理办法》（总局令 47 号）、《医疗器械软件注册审查指导原则（2022 修订版）》；待核实项含 NMPA AI 器械注册审查指导原则条款号、FDA 多项指南的年份/标题、CMDE「算法复用」征求意见稿等。

> **诚实标注**：依据登记表存在大量 `待核实` 项，意味着判定器的法规溯源**尚未完成原文核对**，在条款号级不可作为正式引用。

## §3 回测设计（Backtest Design — 方案，未执行）

本节定义**拟执行**的回测协议。所有指标均为"将计算"而非"已计算"。

### 3.1 样本来源（Sample Sources — 待采集）

| 样本类别 | 目标规模 | 状态 | 所需授权 / 出处 |
|---|---|---|---|
| 脱敏企业变更记录 | ≥20 例（试点）/ ≥500 例（白皮书） | **未采集** | 厂商书面授权；来源文件 `立项书-ACD-MD-001.md` 将 ≥500 列为 6 个月目标 |
| 公开监管裁决 / 申报案例 | 待定 | **未采集** | FDA 510(k) 软件变更相关公开材料、CMDE 公开意见等 |
| 合成示意案例（仅用于流程演示） | 3 例（已存在） | 已有，但**非实证** | 来源文件 `框1...初稿.md` §4，明确标注"非真实企业数据" |

### 3.2 判据（Judgment Protocol）

- **输入标准化**：将每例变更记录编码为（变更类型集合，目标市场，PCCP 状态）三元组，交由判定器输出档位。
- **金标准构建**：由 ≥2 名独立合规/注册专家对同批样本盲法给出档位，作为 reference standard。
- **分歧仲裁**：专家间不一致者由第三名资深专家仲裁或记"悬置"。

### 3.3 一致性度量方式（Agreement Metrics — 将计算）

- **Cohen's Kappa**（判定器 vs 金标准，以及专家间）：报告 κ 值与 95% CI。
- **一致率（Percent Agreement）** 与 **Gwet's AC1**：用于校正类别不平衡导致的虚高一致率。
- **分歧归因（Divergence Attribution）**：对每一处不一致，归因为 {规则歧义 / 依据待核实 / 多变更组合效应 / 市场特定路径差异 / 输入编码偏差} 之一，形成归因频数表。
- **RQ1 内部可复现性**：同输入重复运行 N 次，报告输出一致率（理论 100%）。

### 3.4 敏感性分析（ planned）

- 对 `待核实` 依据项做保守/宽松两版映射，观察档位分布漂移。
- 移除"就高原则"改"加权平均"，观察与专家一致性变化。
