## 1. 术语定义

**Culpachain**（多智能体问责治理）关注**一条自治智能体链上的问责**：当多个智能体顺次或协同行动时，谁来回答？其词源由 **culpa-**（拉丁语"过失、责任"，同源 culpability）与 **chain**（链）拼接而成，字面即"责任沿其分布的链"——它命名的是责任被分布其上、且必须被重新解析的那条结构对象。

核心命题：单智能体治理有简单答案——智能体的 owner 担责。多智能体系统打破这一点：智能体 A 规划、B 执行、C 在失败后重试，结果是链的涌现产物。损害真实，而责任方**沿链分布**。Culpachain 主张问责必须**沿链解析（chain-resolved）**，而非按单体解析（agent-resolved）：

- **有籍（LGD-I）**：链上每一环都被登记——角色、权限范围、交接边界。人类根（origin）永不变；每跳有类型身份（agentProfileId）与运行身份（agentRunId）之分。
- **有证（LGD-II）**：每次交接都留痕迹——输入、决策、输出，以及**委托行为本身**（谁把任务交给谁）。传递式问责：B 须对 C 的产出负责，并向 A 提供完整签名证据链。
- **有门禁（LGD-III）**：责任在交接处被门禁——一跳不得接受其权限无法履行的 task，也不得传递其无法对结果负责的 task；权限只收窄不放宽，撤销一跳即失效其后所有跳。

**作为治理对象的判定**：一段多智能体协作是否落入 Culpachain 管辖，看它是否满足——是否存在**委托**（一跳把任务交给另一跳）？委托是否跨运行身份？是否产生需归责的产出？三问皆否的单体智能体不归本角度；有一则须按链治理。这条判定把"链式委托"从隐式调用图显式切分为"该管的链"与"不必管的单体"。

**责任真空分类学**：按缺失维度，责任蒸发有四类——① 授权蒸发：无一环持完整授权证据；② 意图漂移：原始意图逐跳变形，无人对漂移负责；③ 责任稀释：涌现损害下每跳都"只做了一部分"；④ 撤销失效：撤销一跳后下游仍运行。四类共同特征：链籍缺失、交接证据缺失、链式门禁未过。

**占位与命名纪律（与 README 自洽）**：描述性英文名 *Multi-Agent Accountability* 已被既有文献占据——既有具名理论（如"问责边界理论"与某问责框架 AAF）已框架化该描述名。"委托链 / delegation chain"命名空间亦被强占（已有开放委托链规范、智能体身份与委托链的标准化草案、链完整性形式化论文、某前沿实验室的传递式问责研究）。因此本角度定名 LGD 原生铸词 **Culpachain**（理论层零占位），通用描述名降为副名承载检索。本角度**不争描述名、不争链数据结构首创**，主张落在"治理元结构（三律链式化）"。

## 2. 问题陈述

智能体时代最尖锐的治理缺口，是**多跳委托后的责任真空**：用户让助手办事，助手调子智能体，子智能体调第三方工具——一条链跑完，出事时**没人能回答"这步是谁授权的、原始意图是什么、在哪一跳越了界"**。多主体问责被多个监管讨论列为未决缺口之一；学术界已确认这是智能体 AI 的核心风险。

现行框架（各类访问控制、静态安全过滤器）都假设"智能体是单体"，无法处理"链式委托"。具体失败模式即上文四类责任真空。根因是：治理对象被错误地设定为"单个智能体"，而真实的风险载体是"整条委托链"。Culpachain 的切入点：把整条链当作一等治理对象，链上每一跳都过 LGD 三律。

**治理成熟度缺口（单体假设 vs 链假设）**：现行访问控制与审计多基于"单体可追责"假设（L0/L1 清单态，记录单点），未形式化"链上传递式问责"（L2 规则态，校验权限收窄与级联撤销）。当智能体开始互相派活，单体假设直接破裂，审计只能还原单跳、不能还原整链。Culpachain 要求把问责升到 L2：链可解析、可复放、可级联撤销。

## 3. 与 LGD 母理论的关系（在六层理论栈中的位置）

Culpachain 属于**横向 2 · 角度层**（TH-ANG-003），将 LGD 三律**链式化**地投射到"多智能体委托"这一结构上。

- **公理层（LGD 三律）**：链上身份登记 = 有籍；交接证据链 = 有证；交接门禁 = 有门禁。
- **制度层**：把"委托链"从技术调用图提升为治理对象，明确每一跳的权责边界。
- **证据层**：交接证据（输入/决策/输出/委托行为签名）是 LGD-II 在链上的工件；传递式问责依赖可复放签名链。
- **判定层**：交接门禁（能否接受/能否传递）是对"该跳是否具备担责能力"的判定，输出四态。
- **实例层**：在 13 域映射为具体问责母版（见 §5）。
- **回灌层**：跨域链实践反哺——如金融交易中"连带责任的法理"可回灌为链上责任分布的治理范式。

**与相邻角度的耦合**：链上记忆的共享须过记忆门禁（与 Mnemoship 相交）；链末端往往是退役，须先结清链上责任（与 Terminance 相交）；链上每一跳的实时行为越界，是运行时门禁的监测对象（与 Runtigil 相交）；链治理的成熟度可作为承保依据（与 Assurability 相交）。

## 4. 方法要点

Culpachain 给出"问责沿链解析"的执行方法，分登记、证据、门禁三步，并附"委托链最小数据模型"与"链问责成熟度分级"。

**（一）链式身份登记（有籍）**
1. 固定人类根（origin）：链的源头永远是可追溯的自然人/组织，运行中不变。
2. 区分类型身份与运行身份：agentProfileId（这类智能体能做什么）vs agentRunId（这次运行实例），二者分离。
3. 登记每跳的角色、权限范围、交接边界。

**（二）链式证据（有证）**
对每次交接，至少留四类痕迹：
- **授权范围**：本跳 scope、可用工具、预算余量、委托时间戳。
- **执行记录**：本跳实际做了什么、产出什么。
- **委托行为**：谁把任务交给谁、基于何授权。
- **传递式签名**：B 对 C 的产出签名负责，并向 A 提供完整证据链。

**（三）链式门禁（有门禁）**
- **权限收窄门禁**：effective_child = intersect(effective_parent, profile_child)，只收窄不放宽。
- **预算传播门禁**：budget_child = min(remaining_parent, max_child)，不超额。
- **循环预防门禁**：同一智能体不得在链中出现两次。
- **级联撤销门禁**：撤销一跳，其后所有跳立即失效。

**（四）委托链最小数据模型**
一条链至少应可机读表达：人类根、各跳的身份对（profile/run）、每跳 scope 与预算、每次交接的委托行为签名、每跳的执行记录、级联撤销关系。该模型是"链上有籍+链上有证"的机器可读载体，使整链可复放、可追责。

**（五）链问责成熟度分级（L0–L3）**
- **L0 单体态**：只记录单点，无链视图。
- **L1 清单态**：链可列出，人工核对每跳。
- **L2 规则态**：权限收窄/预算传播/循环/级联撤销可自动校验。
- **L3 代码态**：传递式签名由代码强制，撤销即失效。
Culpachain 要求强监管域达 L2/L3。

**（六）链问责就绪度自评（落地清单）**
- [ ] 有籍吗：人类根可追溯？每跳身份分离登记？ 否 → 先补链籍。
- [ ] 有证吗：每次交接的输入/决策/输出/委托行为可查？ 否 → 补证据链。
- [ ] 权限只收窄吗：下游 scope 不超出上游？ 否 → 卡权限门禁。
- [ ] 可级联撤销吗：撤销一跳能失效其后？ 否 → 记为判定债务。
- [ ] 无循环吗：同智能体不重复出现？ 否 → 卡循环门禁。

可判定性遵循 LGD 判定论：门禁判据形式化 ≥ L1，输出四态；要素缺失显式悬置。

**（七）多智能体问责微型示例**
用户委托研究助手 A 撰写报告；A 调用检索子智能体 B 收集资料；B 调用第三方工具 C 抓取网页。C 抓到一处被篡改的来源，B 未校验即纳入，A 未溯源即成文，报告据此给出错误结论并造成损失。沿链解析：人类根 = 用户；A 的 scope 含"撰写报告"，B 的 scope 含"检索"，C 的 scope 含"抓取"；权限逐跳收窄（A⊇B⊇C）。责任不在任一单体：C 越界（未校验来源）、B 越界（未留委托行为证据链）、A 越界（未对 C 产出签名负责）。级联撤销：撤销 C，则 B、A 的下游失效，整链回到人工复核。该例说明——问责只能沿链解析，不能按单体追。

**（八）链式问责的形式化直觉**
链式问责成立依赖两条不变量：① 人类根不变量——链头永远是可追溯的自然人/组织，运行中不变；② 权限单调不变量——effective_scope 沿链只收窄。两条任一被破坏，链即不可解析：根可变则责任无锚，权限可放大则下游能做出上游从未授权的事。Culpachain 的工程化，就是把这两条不变量编码为可机读校验，使"链可解析"成为可判定的性质，而非事后归责的修辞。

**（九）链治理的可观测信号**
判断一条委托链的问责是否落到实处，看三_signal：① 每跳可签名——每次交接都带委托行为签名，无"无名交接"；② 撤销可传播——撤销任一跳，其下游在限定时间内全部失效，无"悬空下游"；③ 根可追溯——从任意一跳都能回溯到人类根，无"断头链"。三_signal皆备，问责才能沿链解析；任一缺失，责任便在链上蒸发。这三条把"多主体问责"从监管讨论翻译成工程侧可点检的清单，也是金融连带责任法理、产品责任法在智能体时代的落地抓手。



**（十）委托链的工程落地形态**
链问责不必从零构建：既有开放委托链规范已给出可复用的结构——每跳携带类型身份与运行身份、交接带委托行为签名、权限按交集收窄、撤销可级联传播。Culpachain 的增量贡献不在重造这条链，而在把 LGD 三律显式叠加上去：链籍（每跳登记）、链证（交接留痕）、链门禁（权限收窄与级联撤销）。当工程链与治理三律对齐，监管、承保与用户三方都能用同一套语言谈论"这条链是否可问责"，命名之争让位于结构之治。


## 6. 边界与不适用范围

Culpachain 明确**不解决**以下事项：

- **不解决链的数据结构**：委托链如何序列化、如何传输是技术规范；本角度只规定链上每跳须登记、留证、设门禁。
- **不主张"委托链"命名**：该命名空间已被既有开放规范与标准草案占据，本角度以 Culpachain 承载主张，不与规范制定权竞争。
- **不给出责任分配的数学解**：责任在链上的最终法律分配，受"问责地平线"等不可能性结果约束，本角度只提供治理结构，不声称突破数学不可能。
- **不覆盖单体智能体**：单智能体问责归既有框架；本角度专治"链式委托"。
- **不提供法律意见**：具体责任认定以当地法律与司法实践为准。
- **不声称已被任何标准或监管采用**：外部引用与采纳目前为零；本角度为民间理论发布物，非法律意见、非技术规范。

**（十）五角度协同总表**
本文角度并非孤立切面，它与跨域角度矩阵其余四角度在治理结构上自然耦合：

| 相邻角度 | 与本文角度的交点 |
|---|---|
| Terminance｜退役往往发生在链末端，须先结清链上责任再注销 |
| Mnemoship｜链上记忆共享须过记忆门禁，防记忆随委托外溢 |
| Runtigil｜链上每跳的实时行为越界，由运行时门禁监测与拦截 |
| Assurability｜链治理成熟度（可签名/可撤销/可追溯）作为承保依据 |

这张表说明：五个角度（退役、记忆、问责、运行时、可保性）不是五篇平行文章，而是同一套 LGD 三律在五个不同切面上的展开；任一自治之物的完整治理，都需要五者在对应时点同时生效。



**（十一）收口命题**
问责不是追一个人，是追一条链。当自治之物开始互相派活，治理的唯一诚实姿态，是把整条委托链当作一等对象，让链上每一跳都可登记、可留证、可设门禁。Culpachain 把这一姿态收敛为 LGD 三律的链式化表达，使"多主体问责"从监管难题变成可点检、可复放、可级联撤销的治理结构。


在强监管域（金融、法律），链式问责应优先达到 L2/L3，使级联撤销与权限收窄可由代码强制，而非依赖人工核对。
