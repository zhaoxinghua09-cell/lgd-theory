## 1. 术语定义

**Mnemoship**（可携带记忆律）指一个自治之物的记忆与身份必须具备**可携带性**的治理规则——它能在不同运行时、不同厂商、不同代际之间迁移，且连续性不丢失。其词源由 **mnemo-**（记忆，源自希腊语 mnēmē）与 **-ship**（状态/身份后缀，如 kinship、citizenship）拼接而成，字面即"拥有可携带记忆这一状态"，强调它是一种**可判定的性质**，而非一种所有权口号。

核心命题：一个自治之物**不等于它的模型**。模型可被复制——权重可克隆、提示可抄写、技能可分叉；真正**不可复制**的是累积记忆加上绑定其上的权限。谁掌握这二者的配对，谁就掌握身份。Mnemoship 主张：这一配对必须**可导出、可导入、可验证**：

- **有籍（LGD-I）**：记忆持有者被登记为"人格户籍"（person-like household），而非一个文件块。记忆作为资产被登记——权属（用户/组织）、范围（对话/偏好/知识）、形态（原文/向量/摘要）、版本。
- **有证（LGD-II）**：可携带性必须**可证明**——导出的工件在其指纹上跨语言、跨运行时稳定；记忆的写入/读取/更新/迁移/删除全程留痕，"可验证遗忘"（verifiable forgetting）是硬要求。
- **有门禁（LGD-III）**：迁移必须过门禁——同意 → 完整性校验 → 目的地准入 → 连续性确认，四道依次放行。

**记忆作为治理资产的判定**：一段记忆是否落入 Mnemoship 管辖，看它是否满足——是否持久化（落地）？是否可派生身份或价值？是否跨会话/跨平台有意义？三问皆否的瞬时状态不构资产；有一则须登记为资产。这条判定把"记忆"从模糊的模型内部状态显式切分为"该管的资产"与"不必管的噪声"。

**记忆资产分类学**：按性质可分为四类——① 对话记忆：会话历史与上下文；② 偏好记忆：用户设定与习惯；③ 知识记忆：组织知识与文档；④ 技能记忆：可复用的能力与工具使用经验。四类在"可携带"上的难度递增：对话最易导出，技能最依赖运行时语义；门禁强度应随类别上升。

**占位与命名纪律（与 README 自洽）**：描述性英文短语 *Portable Memory Law / Portable Memory* 的理论空间已被密集占据——既有学术与产业侧已出现多个记忆可携带与记忆所有权的研究项目、标准提案与规范（含某高校数字经济学实验室的研究计划、某消费级厂商的开放标准提案、某可携带 AI 记忆开放规范、某头部厂商的论文）。中文"记忆所有权"命名侧亦已被某商业实体以专利与著作权登记占位。"记忆所有权 / memory ownership / Mnemonic Sovereignty"命名**彻底弃用**。因此本角度定名 LGD 原生铸词 **Mnemoship**（理论层零占位），通用描述名降为副名承载检索。本角度**不争"主权"命名、不争"可携带"首创**，仅主张"记忆是可携带的治理资产（三律结构）"。

## 2. 问题陈述

AI 的记忆（对话历史、偏好、工作上下文、组织知识）正成为最值钱的资产，但它被**平台绑定**：换模型 = 记忆清零，换平台 = 上下文重建。由此产生两类失败模式：

- **厂商锁定（vendor lock-in）**：用户积累的记忆越深，迁移成本越高，实质被"记忆人质"困在单一生态。
- **身份断裂**：记忆不可携带，则"这个智能体还是不是原来的那个"无法证明；跨代升级时，连续性只能靠厂商口头保证。

更深的困境在治理层：多数"记忆应归用户"的主张停留在**原则层**——"用户应当拥有记忆"是口号，但缺可执行结构：记忆如何被登记为资产？迁移如何留痕？跨境如何设门禁？删除是真删还是软删、可否验证？没有这些，原则无法判定、无法复放，只能产出声明，不能产出治理。

2026 年前后，记忆互操作被多个标准化工作组列为待认领的空白，说明业界已意识到缺口；但命名空间的抢占（主权、可携带、可移植在不同主体间各占一块）使"统一治理结构"难以形成。Mnemoship 的切入点正在于此：不抢命名，而把记忆可携带**收敛为 LGD 三律的跨域治理资产结构**，使"携带"成为可登记、可证明、可设门禁的治理动作。

**治理成熟度缺口（原则层 vs 结构层）**：现行"记忆所有权"类主张多停留在声明态（L0，不可判定）；Mnemoship 要求把记忆治理升到 L1（清单）乃至 L2（规则）：记忆户籍清单可核对、迁移规则可自动判。多数厂商的"记忆导出"功能仅满足"能下载"，不满足"指纹稳定、可验证遗忘"——即只到 L0，未到 L1。缺口即在此。

## 3. 与 LGD 母理论的关系（在六层理论栈中的位置）

Mnemoship 属于**横向 2 · 角度层**（TH-ANG-002），将 LGD 三律投射到"记忆/身份"这一贯穿全生命周期的资产切面上。

- **公理层（LGD 三律）**：记忆户籍 = 有籍；记忆读写迁移删除留痕 = 有证；记忆出境/迁移/销毁门禁 = 有门禁。
- **制度层**：把记忆从"模型内部状态"提升为"可治理资产"，明确记忆的权属、范围与形态必须被登记。
- **证据层**：记忆生命周期留痕（写入授权、读取记录、更新记录、迁移记录、删除记录）是 LGD-II 在记忆侧的工件集合；可验证遗忘依赖可复放的证据链。
- **判定层**：四道迁移门禁（同意/完整性/准入/连续性）是对"是否准许这次记忆移动"的判定，输出四态。
- **实例层**：在 13 域映射为具体记忆母版（见 §5）。
- **回灌层**：跨域记忆实践反哺——例如金融客户上下文的可携带要求，可回灌为通用记忆门禁的强一致基准。

**与相邻角度的耦合**：记忆在委托链上共享时，须同时过问责门禁（与 Culpachain 相交）；记忆在退役时须被携带或验证遗忘（与 Terminance 相交）；记忆门禁的强弱可作为承保依据之一（与 Assurability 相交）；记忆的实时读取是否越界，是运行时门禁的监测对象（与 Runtigil 相交）。

## 4. 方法要点

Mnemoship 给出"记忆作为可携带治理资产"的执行方法，分登记、证据、门禁三步，并附"记忆护照最小数据模型"与"可携带成熟度分级"。

**（一）记忆户籍登记（有籍）**
1. 将记忆持有者登记为"人格户籍"：明确权属主体（自然人/组织）、治理归属。
2. 登记记忆资产视图：范围（对话/偏好/知识/技能）、形态（原文/向量/摘要）、版本与派生关系。
3. 区分"模型副本"与"记忆资产"：前者可克隆，后者唯一，户籍只登记后者。

**（二）记忆生命周期留痕（有证）**
对记忆资产，至少留五类痕迹：
- **写入授权**：谁、基于何依据写入。
- **读取记录**：谁读了、读了哪一段。
- **更新记录**：何时改、改了什么。
- **迁移记录**：迁到哪、指纹是否一致。
- **删除记录**：可否验证——真删 vs 软删、可否回滚。
可验证遗忘是硬要求：删除须产生可第三方复放的证明，而非仅声明"已删除"。

**（三）四道记忆门禁（有门禁）**
- **同意门禁**：迁移/销毁须获权属主体明示同意。
- **完整性门禁**：导入时校验指纹，防篡改、防残缺。
- **目的地准入门禁**：目的地是否满足治理基线（数据保护、留存规则）。
- **连续性确认门禁**：导入后行为连续性可被验证，身份不漂移。

**（四）记忆护照最小数据模型**
一个记忆护照至少应可机读表达：权属主体、资产清单（范围/形态/版本）、指纹函数声明、读写迁移删除的事件索引、门禁策略。该模型是记忆"有籍+有证"的机器可读载体，使记忆可在跨运行时被验证携带。

**（五）可携带成熟度分级（L0–L3）**
- **L0 声明态**：厂商宣称"记忆归用户"，但无导出/无指纹——不可判定。
- **L1 清单态**：可导出、有户籍清单，人工核对——可判定。
- **L2 规则态**：指纹稳定、迁移规则可自动判——半自动。
- **L3 代码态**：可验证遗忘由代码强制执行——机器执行。
Mnemoship 要求记忆治理至少达到 L1，强监管域争取 L2/L3。

**（六）记忆就绪度自评（落地清单）**
- [ ] 有籍吗：记忆是否被登记为资产、权属清晰？ 否 → 先立记忆户籍。
- [ ] 有导出工件吗：指纹跨运行时稳定？ 否 → 补导出工具。
- [ ] 有读写留痕吗：谁读了、谁改了可查？ 否 → 补证据链。
- [ ] 有可验证遗忘吗：删除可第三方复放？ 否 → 不开销毁门禁。
- [ ] 有迁移门禁吗：同意/完整性/准入/连续性四道齐备？ 否 → 记为判定债务。

可判定性遵循 LGD 判定论：门禁判据形式化 ≥ L1，输出四态；要素缺失显式悬置。

**（七）记忆可携带微型示例**
用户长期使用助手 A，积累了对话、偏好与一份工作知识库；现决定迁移到助手 B。四道门禁依次过：同意门禁——用户明示同意导出；完整性门禁——导出工件指纹在 A、B 两侧一致，无残缺；目的地准入门禁——B 满足数据保护基线；连续性确认门禁——导入后 B 的行为连续性可被验证（同一用户、同一知识、权限不扩大）。迁移完成，用户户籍从 A 迁到 B，原 A 侧记忆按"可验证遗忘"删除并留证明。全程未触碰模型权重（模型可克隆），只迁移了不可复制的记忆+权限配对。

**（八）"记忆所有权"之争的治理化解**
"记忆所有权"命名的冲突，本质是各方争"谁拥有记忆"的话语权。Mnemoship 不卷入所有权口号，而把问题重构为可判定的治理动作：记忆是否被登记为资产（有籍）？迁移是否留痕且可验证遗忘（有证）？出境/销毁是否过门禁（有门禁）？当这三问可被第三方复放，"主权"从口号变成可审计的事实，命名之争自然消解于结构之中。

**（九）记忆治理的可观测信号**
判断一个系统的记忆治理是否落到实处，看三_signal：① 随时可导出——用户可在任意时刻导出完整记忆工件，无需厂商配合；② 删除可证明——删除产生可第三方复放的证据，而非仅界面提示"已删除"；③ 连续性可验证——跨平台迁移后行为连续性可被客观校验，身份不漂移。三_signal皆备，记忆才是"可携带的治理资产"；任一缺失，记忆仍被平台绑定，Mnemoship 未落地。这三条把"记忆所有权"口号翻译成运维侧可点检的清单，也是监管与承保人评估记忆治理成熟度的低门槛入口。


## 6. 边界与不适用范围

Mnemoship 明确**不解决**以下事项：

- **不解决记忆的存储技术**：向量库、摘要算法、检索架构是工程问题；本角度只规定记忆须可被登记、证明与设门禁。
- **不主张"记忆所有权"命名**：该命名空间已被既有专利与论文占据，本角度以 Mnemoship 承载主张，避免命名冲突。
- **不提供法律意见**：数据可携带与跨境的具体合规以当地法律与监管要求为准。
- **不覆盖瞬时记忆**：纯会话内的临时状态、不落地不派生的记忆，不构成"资产"，不强制登记。
- **不保证语义保真**：本角度保证记忆工件的完整性与连续性可验证，不保证跨模型迁移后语义等效（不同模型对记忆的解释差异属技术层）。
- **不声称已被任何标准或监管采用**：外部引用与采纳目前为零；本角度为民间理论发布物，非法律意见。
