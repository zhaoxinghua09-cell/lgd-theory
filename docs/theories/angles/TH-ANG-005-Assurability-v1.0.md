## 1. 术语定义

**Assurability**（可保性治理）指一个对象**可被承保**这一性质，且把它当作**治理的输出**，而非精算的偶然。其词源由 **assurable**（可承保的）加 **-ity**（状态/性质后缀）构成，字面即"处于可承保的状态"。它对应的中文主名为「可保性治理」，描述性副名为 *Governance-Conditioned Insurability*。

核心命题：保险是现存最古老的治理技术之一。它不消除风险，而是让风险**被定价、被池化、被问责**。承保人向来把治理作为承保条件——消防规范、适航性、网络卫生，皆是其例。一个无法被承保的自治之物，不只是"风险大"，而是**未被治理**：因为没有第三方愿意为它的失败定价。

Assurability 主张：可保性由治理**工程化地造就**，且可被检验：

- **有籍（LGD-I）**：被保险对象必须可识别——保的到底是什么、哪个版本、在谁的权限下。
- **有证（LGD-II）**：风险必须可证明——已文档化的控制、事件历史、变更记录，构成核保档案（underwriting file）。"合规级可观测性"是核保的硬门槛。
- **有门禁（LGD-III）**：承保必须**以门禁为条件**——保费与条款随可证明的门禁表现调整，门禁失效则承保中止。

**作为治理输出的判定**：一个对象是否"可保"，在 Assurability 框架下被还原为三问——风险主体可识别（有籍）？治理证据可观测（有证）？承保以持续门禁为条件（有门禁）？三问皆过，则可保性高；有一不过，则不可保或仅"条件承保/悬置"。这条判定把"能不能保"从精算黑箱显式拆为治理三律的可判定组合。

**不可保分类学**：按缺失维度，不可保有四类——① 不可识别：标的/版本/权限不清，无法登记；② 不可证明：无治理证据，承保人无法观测风险；③ 不可持续：有证据但门禁不持续，承保期失控；④ 不可定价：纯自然/市场风险，非治理维度。前三类是 Assurability 的治理对象，第四类不在本角度范围。

**占位与命名纪律（与 README 自洽）**：描述性短语 *Governance-Conditioned Insurability / AI Insurability* 的名称空间已被占据——既有从业者论述（如"保险无法为治理无法证明的风险定价"的洞察）、某"再保险 AI"架构论文、某"面向智能体的 AI 原生保险"框架（提出可保性区域与治理认证阈值）均已占位；"insurability"本身是行业标准词，不具独占性。因此本角度定名 LGD 原生铸词 **Assurability**（理论层零占位，作为技术名词此前未被占用），通用描述名降为副名承载检索。本角度**不宣称对"可保性"因果发现的首创**，主张落在"治理结构是可保性的前提（可保性=治理的函数）"，对既有洞察作领域呼应。

## 2. 问题陈述

2026 年前后，AI 责任险市场出现一个悖论：**一边是保险产品密集上线**（多家承保人推出面向 AI 的责任与性能保证险），**一边是绝对排除条款同步扩张**（多家承保人明确排除生成式 AI 损失）。报告显示：AI 原生风险（幻觉、算法偏见、模型漂移）在主要险种中都存在覆盖缺口——既不明确承保也不明确排除，即"未定价、未管理"。

根因不是"风险不可度量"，而是**治理不可证明**。核保需要"纯风险、可量化、偶然、可测"四要件，而 AI 的黑箱让承保人无法观察风险。没有可证明的治理，就没有可定价的对象。

历史的答案在航空史：20 世纪初航空曾被认为"不可保"，直到承保人联合建立"逐机检查 + 逐飞行员测试"的检验制度后，保费才下降。**保险定价的不是风险本身，而是审计纪律。** 治理制度先于可保性——这一排序对自治之物同样成立。Assurability 的切入点：把"能否被承保"显式设计为治理的产出函数，使治理证据直接成为核保可读的输入。

**治理成熟度缺口（声明 vs 证据）**：多数 AI 系统的治理处在 L0（声明态，自称"负责任"），承保人无法观测，故只能"silent AI"——既不保也不免。Assurability 要求升到 L1/L2：治理证据可观测、门禁持续有效，使"可保性"从不可判定变为可判定。

## 3. 与 LGD 母理论的关系（在六层理论栈中的位置）

Assurability 属于**横向 2 · 角度层**（TH-ANG-005），将 LGD 三律**投射为核保的三类输入**。

- **公理层（LGD 三律）**：风险主体登记 = 有籍（核保标的）；治理证据 = 有证（核保依据）；持续门禁 = 有门禁（承保条件）。
- **制度层**：把"可保性"从精算结果提升为治理产出，明确治理成熟度是可保性的前置变量。
- **证据层**：治理证据链（不可篡改审计、版本化输出、带时间戳引用、签名变更日志）是 LGD-II 在核保侧的工件；合规级可观测性是硬门槛。
- **判定层**：承保条件门禁（认证前置/持续评估/限额排除/理赔触发）是对"是否持续满足承保"的判定，输出四态。
- **实例层**：在 13 域映射为具体可保性母版（见 §5）。
- **回灌层**：跨域承保实践反哺——如航空适航、船舶适航的"认证→可保"范式，回灌为通用可保性门禁的强度基准。

**与相邻角度的耦合**：承保标的的退役触发保单终止（与 Terminance 相交）；记忆门禁强弱影响承保（与 Mnemoship 相交）；链上问责完整度影响承保（与 Culpachain 相交）；运行时门禁的触发与强度是持续评估的直接信号（与 Runtigil 相交）。五角度中，Assurability 是"外部第三方愿意为治理定价"的收口验证。

## 4. 方法要点

Assurability 给出"把治理变成可保性"的执行方法，分登记、证据、门禁三步，并附"核保档案最小数据模型"与"可保性成熟度分级"。

**（一）风险主体与保单登记（有籍）**
1. 登记谁投保、保什么（第三方责任/性能保证/专业赔偿）、标的（模型/智能体/系统）、风险分层。
2. 无登记则无法承保——户籍是核保的起点。

**（二）治理证据 = 核保依据（有证）**
核保档案至少含四类证据：
- **控制证据**：已文档化的治理控制（认证、策略、流程）。
- **事件证据**：事件历史与处置记录。
- **变更证据**：版本化提示与输出、带时间戳的检索引用。
- **审计证据**：安全设置的签名变更日志、不可篡改审计链。
"合规级可观测性"是核保硬门槛——证明你管住了风险，而不是声明你管住了。

**（三）承保条件门禁（有门禁）**
- **认证前置门禁**：如通过国际 AI 管理体系标准认证 → 优先获得保险。
- **持续评估门禁**：承保期须持续满足模型质量与门禁表现。
- **限额与排除门禁**：超限或触发排除项即调整或终止。
- **理赔触发门禁**：治理失效影响赔付——门禁失效，承保中止。

**（四）核保档案最小数据模型**
至少应可机读表达：标的标识与版本、风险分层、四类证据索引（控制/事件/变更/审计）、门禁表现序列、承保条件状态。该模型是"有籍+有证"的机器可读载体，使治理证据可被核保人直接读取与复放。

**（五）可保性成熟度分级（L0–L3）**
- **L0 声明态**：自称负责任，无证据——不可保（silent）。
- **L1 清单态**：治理证据可核对——条件承保。
- **L2 规则态**：证据可自动读、门禁持续可校验——优先承保。
- **L3 代码态**：治理失效自动触发承保中止——最佳。
Assurability 推动域从 L0 向 L2/L3 演进。

**（六）可保性就绪度自评（落地清单）**
- [ ] 有籍吗：标的、版本、权限可识别？ 否 → 先补登记。
- [ ] 有证吗：控制/事件/变更/审计四类证据齐全且可观测？ 否 → 补核保档案。
- [ ] 有认证吗：通过治理认证？ 否 → 卡认证前置门禁。
- [ ] 可持续吗：承保期门禁持续有效？ 否 → 记为判定债务。
- [ ] 有终止条件吗：治理失效即中止承保？ 否 → 补理赔门禁。

可判定性遵循 LGD 判定论：门禁判据形式化 ≥ L1，输出四态；要素缺失显式悬置。

---


**（七）可保性治理微型示例**
某 AI 放贷机构欲投保第三方责任险。核保人要求：有籍——标的（放贷模型 v3.2）、版本、权限清晰；有证——控制证据（已通过治理认证）、事件证据（误拒/误贷事件台账）、变更证据（模型迭代带时间戳）、审计证据（不可篡改审计链）；有门禁——承保以持续门禁为条件，治理失效即中止。该机构达标 L2，获优先承保、保费随门禁表现调整。另一机构仅 L0（自称负责任、无证据），核保人无法观测风险，列为"silent AI"既不保也不免。同是 AI 放贷，可保性之分不在风险大小，而在治理能否被证明。

**（八）"治理先于可保"的范式迁移**
航空与船舶史表明：可保性不是风险的天然属性，而是治理制度的产物——先有检验制度，后有可保。Assurability 把这一范式迁移到自治之物：可保性 = 治理的函数。这意味着提升可保性的杠杆不在精算端，而在治理端——把三律做扎实，承保自然可期。本角度不承诺任何承保人必然承保，只主张"治理是可保性的前置变量"这一可检验的命题。


## 5. 跨域适用性

可保性横贯所有域，且域的成熟度高低直接由"治理可被证明"的程度决定。13 域映射如下：

| 域（TID） | 母版参照 | LGD 平移 |
|---|---|---|
| 航空（映射 AUT/IND） | 适航认证 → 可保性 | 成熟历史范式：治理先于可保 |
| 船舶（映射 CRYPT/ENE） | 适航性 → 船壳险 | 最古老实例 |
| 医疗 MED | 责任险以质量管理体系证据为条件 | 行业类比 |
| 金融 FIN | 模型风险险以治理证据为核保依据 | 金融可保性 |
| 自动驾驶 AUT | 自动驾驶责任险以运行门禁为条件 | 车载可保性 |
| 低空 UAS | 无人机责任险以飞行门禁为条件 | 载具可保性 |
| 机器人 ROB | 具身责任险以动作门禁为条件 | 物理可保性 |
| 工业 IND | 产线责任险以调度门禁为条件 | 调度可保性 |
| 能源 ENE | 运维责任险以运维门禁为条件 | 运维可保性 |
| 数据 DAT | 数据责任险以处置证据为条件 | 数据可保性 |
| 法律 LAW | 自动化决策责任险以合规证据为条件 | 法律可保性 |
| 政务 GOV | 公共责任险以合规证据为条件 | 公共可保性 |
| 生物基因 BIO | 基因责任险以受控证据为条件 | 敏感可保性 |
| 教育 EDU | 教学责任险以教学门禁为条件 | 教学可保性 |

最先落地的域是 **MED（医疗器械）与 FIN（金融）**：前者责任险本就以质量管理体系证据为承保条件，后者模型风险险已要求治理证据。历史范式上，**航空适航认证→可保性**是最成熟的参照——它证明了"治理制度先于可保性"的因果次序，Assurability 只是把这一次序形式化为自治之物的通用角度。映射方法：取该域既有"认证/适航→承保"范式，填充"标的登记/核保证据/承保门禁"三栏，缺口显式标注。回灌侧：航空与船舶的"认证→可保"强度基准，可抬升通用可保性门禁的下限——治理认证须达强制阈值，而非自愿声明。

**（九）可保性的可观测信号**
判断一个对象的可保性是否由治理造就，看三_signal：① 档案可读——核保人能直接读取治理证据，无需对象方口头解释；② 保费联动——保费与门禁表现挂钩，治理好则便宜、治理差则贵或拒保；③ 承保中止——治理失效时承保自动中止，而非依赖事后争议。三_signal皆备，可保性才是治理的函数；若治理证据不可读、保费固定、失效不中止，则仍属"silent AI"，不可保。这三条把"治理先于可保"从史例翻译成承保侧可点检的清单，也是航空适航、船舶适航范式对自治之物的直接迁移。


## 6. 边界与不适用范围

Assurability 明确**不解决**以下事项：

- **不提供保险建议**：具体承保条件、保费、条款以承保人文件与监管规定为准；本角度是治理元结构，非核保意见。
- **不主张"可保性"因果发现的首创**：既有洞察（治理不可证明=不可定价）与具名框架已占位，本角度作领域呼应。
- **不解决精算**：风险如何定价是承保人的精算职能；本角度只规定治理证据须可被核保读取。
- **不覆盖治理之外的风险**：纯自然风险、市场风险的承保不在本角度范围；本角度只处理"治理可被证明"那一维。
- **不保证必然可保**：满足治理门禁提高可保性，不承诺任何承保人必然承保。
- **不声称已被任何标准、保险或监管采用**：外部引用与采纳目前为零；本角度为民间理论发布物，非保险建议、非法律意见。
