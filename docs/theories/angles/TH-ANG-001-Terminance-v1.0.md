# 退役治理 Terminance · LGD 跨域治理角度 #1（TH-ANG-001 · v1.0）

> 一句话主张：退役不是运维收尾，而是一次**治理事件**——凡自治之物退出服役时，同样要"有籍（注销登记）·有证（处置留痕）·有门禁（触发与批准）"，跨域同构。
> 命名：中文主名「退役治理」｜ LGD 铸词（英文主名）**Terminance** ｜ 描述性副名 Retirement Governance / AI Decommissioning。
> 上游：TH-ANG-000（跨域治理角度矩阵）、TH-META-006（LGD 全程治理论）、TH-META-001（RRM 真实世界参照法）。
> 诚实定位：本角度**不宣称首创"退役"这一概念**；主张落在"退役是与准入对等的治理事件（跨域同构的三律结构）"，而非单域的 AI 退役流程描述。

## 1. 术语定义

**Terminance**（退役治理）是 LGD 全程治理论中关注"一个自治之物如何结束其服役"的治理学科。其词源由 **termin-**（终止、结束，同源 terminate）与 **-ance**（性质、状态后缀）拼接而成，字面即"终止服役这一治理状态"。它对应的中文主名为「退役治理」，描述性副名为既有的 *Retirement Governance* / *AI Decommissioning*——后者是文献中已形成的通用说法，本铸词不与之争夺，仅承载理论层的品牌主张。

核心定义：退役**不是一个运维清理任务，而是一次治理事件**，其结构与准入（admission）对等。LGD 主张"有籍·有证·有门禁"，退役必须完整复现这三律：

- **有籍（LGD-I）**：退役必须被**登记**。一个没有注销路径的登记是不完整的登记——准入时立了户籍，退役时必须办注销。注销是登记的对称动作。
- **有证（LGD-II）**：退役必须留下**痕迹**。触发依据、处置记录、迁移记录、关机事件、经验捕获（lessons learned），共同构成退役证据链。
- **有门禁（LGD-III）**：退役必须通过**门禁**。触发门禁 → 批准门禁 → 处置门禁 → 替代就绪门禁 → 注销确认门禁，逐道放行。

当这三律缺失时，产生**僵尸系统（zombie systems）**：模型已下线但权重与数据仍在跑；器械已停用但注册证与唯一标识从未注销；设施已关停却无处置证据。Terminance 的命名意义，正是把"退役"这一定位，从生命周期的一个被动阶段，提升为与准入**同等地位**的治理对象。

需要区分"退役"与"删除"：删除是单一动作（抹掉一个文件、停掉一个进程），它不回答"谁批准、为何退、退后依赖谁接替、是否留痕可查"。退役是围绕删除的**治理包裹**——删除只是退役门禁放行后的最后一个技术步骤，而非退役本身。

**退役作为治理事件的判定**：一个退出动作是否构成"Terminance 事件"，看它是否满足三问——是否改变对象的治理状态（有籍变更）？是否产生需留存的证据（有证）？是否经过放行判定（有门禁）？三问皆否，则只是删除；三问有一，则必须按退役事件治理。这条判定把模糊的"下线"动作显式分类，避免以"清理"之名逃避治理。

**僵尸系统分类学**：按缺失维度，僵尸可分为四类——① 模型僵尸：权重副本仍在推理，无注销；② 器械僵尸：注册证与唯一标识未注销，监管台账仍"在用"；③ 资产僵尸：数据资产未销毁、未移交，持续计费与泄露；④ 设施僵尸：物理设施关停但环境责任未闭环。四类共同特征：户籍悬挂、证据缺失、门禁未过。

**占位与命名纪律（与 README 自洽）**：描述性英文名 *Retirement Governance* / *AI Decommissioning* 已在既有文献中被框架化（已有系统综述提出"面向治理的 AI 退役框架"，多个生命周期治理论述均已将退役纳入章节）。因此本角度以 LGD 原生铸词 **Terminance** 作为理论层主名（零占位），通用描述名降为副名承载检索。**本角度不主张对该概念的首创权**，仅主张其跨域同构的治理元结构。

## 2. 问题陈述

现行治理供给存在一个系统性偏斜：**准入端密、退役端疏**。主流人工智能风险框架、国际 AI 管理体系标准、智能体治理画像，均要求"除役程序"，但都只把退役写成生命周期的**一个阶段**（如"部署后监控须含除役""负责任除役"条目），没有把退役当作与准入对等的治理对象——没有统一的退役登记、没有强制的退役证据链、没有独立的退役门禁。

后果是僵尸系统的普遍存在，且跨域一致：

- **AI / 软件**：模型下线了，但权重副本、缓存数据、下游调用链路仍在运行；无注销，等于"活着但没有身份"。
- **医疗器械**：器械停用了，但注册证与唯一器械标识（UDI）未注销，监管台账里它仍是"在用"。
- **工业设施**：工厂或机组关停了，但资产未处置、环境责任未闭环，留下长期隐患。
- **资产 / 设备**：动力电池、卫星等资产退出服役时，缺乏从"在用"到"已处置"的状态闭环。

退役端成为制度洼地，有三类结构性原因：

1. **激励错配**：建设与上线有预算、有考核、有掌声；退役无 KPI、无 owner、无预算，于是"该退不退"。
2. **责任蒸发**：退役往往跨多个团队（研发、运维、合规、资产管理），每段都以为"下一段会管"，结果无人对"全依赖解除"负责。
3. **语焉不详**：治理语言里没有"退役事件"这一一等公民。运维把它当清理，合规把它当收尾，安全往往根本不参与。

最危险的是，退役是风险从"可控"滑向"失控"的最后一关：一个未注销的系统，会在没人看护的情况下继续做决定、继续泄露数据、继续产生责任。2026 年前后密集出现的"AI 除役"文献，正说明业界已意识到这个缺口，但多数仍把它当作单域的收尾流程，而非跨域同构的治理事件。

**治理成熟度缺口（以退役为镜）**：若以四态判定审视现有退役实践——准入（有退出程序）、条件准入（有退出程序但无证据）、禁止（强监管域强制注销）、悬置（程序在途未落地）——多数软件与 AI 系统处于"悬置"：制度宣称要退，但判据未形式化、证据未留存，实际无法复放。Terminance 要补的，正是把"悬置"转为可判定的"准入/条件准入"。

## 3. 与 LGD 母理论的关系（在六层理论栈中的位置）

LGD 理论栈是一条六层主链（公理 → 制度 → 证据 → 判定 → 实例 → 回灌），并叠加两条横切维度（13 域实例化 / 5 角度关切）。Terminance 属于**横向 2 · 角度层**（TH-ANG-001~005），它不另起炉灶，而是把 LGD 三律**投射到"生命周期终段"这一特定切面上**。

- **公理层（LGD 三律）**：退役直接实例化"有籍·有证·有门禁"。注销 = 有籍的闭合动作；处置留痕 = 有证的末端证据；退役门禁 = 有门禁的最后一道判定。
- **制度层**：Terminance 把"退役"从运维制度提升为治理制度，明确退役事件的权责归属与登记义务。
- **证据层**：退役证据链（触发/处置/迁移/关机/经验）是 LGD-II 在终段的证据工件集合，可被事后复放。
- **判定层**：五道退役门禁本质是对"是否准许结束服役"的判定（四态输出：准入/条件准入/禁止/悬置）。
- **实例层**：在 13 域中映射为具体退役母版（见 §5）。
- **回灌层**：跨域退役实践反哺角度定义——例如高风险的核设施退役门禁范式，可回灌为通用退役门禁的强度基准。

在母理论坐标中，Terminance 与 TH-META-006（LGD）是"切面—主干"关系：主干提供三律，切面提供"终段该不该、怎么退"的治理位置坐标系。它不替代任何域框架，只补上"由生到退"闭环中被普遍遗漏的那一截。

**与相邻角度的耦合**：退役不是孤立切面。关机动作本身是一道运行时门禁（与 Runtigil 相交）；退役时记忆与身份的处置必须可携带或可被验证遗忘（与 Mnemoship 相交）；退役若导致保单主体的消灭，承保随之终止（与 Assurability 相交）；退役往往发生在一条委托链的末端，需先结清链上责任（与 Culpachain 相交）。五角度在退役这一终段自然汇合。

## 4. 方法要点

Terminance 给出一套可执行的退役治理方法，分登记、证据、门禁三步，并附"退役就绪度自评"与"退役事件最小数据模型"。

**（一）注销登记（有籍）**
1. 建立退役主体的户籍视图：本体/型号/序列号、模型/版本、资产编号、治理归属。
2. 维护状态机：在用 → 停用 → 已退役 → 已处置。每一次状态跃迁都是一次登记事件，不可静默跳过。
3. 注销是登记的对称动作：凡准入时立了籍，退役时必须能反向闭合，否则户籍处于"悬挂"状态，记为判定债务的存量。

**（二）退役证据链（有证）**
对每一次退役，至少留五类痕迹：
- **触发依据**：为何退（投资回报、技术过时、性能衰减、合规禁止、替代可用）。
- **处置记录**：数据如何处置、模型如何处置、资产如何处置（销毁/归档/移交）。
- **迁移记录**：用户迁移、依赖系统更新、下游调用解耦。
- **关机事件**：实际停止运行的事件留痕（时间戳、操作者、范围）。
- **经验捕获**：lessons learned，供后续同类系统借鉴。

**（三）五道退役门禁（有门禁）**
- **触发门禁**：何时该退——设定触发条件，避免"该退不退"。
- **批准门禁**：谁批准退——含风险分级，高风险退役需更高层级批准。
- **处置门禁**：数据/资产是否合规处置，不合规不得放行。
- **替代就绪门禁**：新系统是否就绪，防止"退了之后无人接替"的服务真空。
- **注销确认门禁**：全依赖是否已解除，确认后方可正式注销。

**（四）退役事件最小数据模型**
一次退役事件至少应可机读地表达以下字段：对象标识、当前状态、触发类型、批准人、处置方式、迁移目标、关机时间、经验条目、门禁轨迹（五道门禁各自 verdict）。该模型是 LGD 三律在退役侧的机器可读载体，使退役可被第三方复放。

**（五）退役就绪度自评（落地清单）**
- [ ] 有籍吗：能否定位它的户籍与当前状态？ 不能 → 先补登记。
- [ ] 有触发依据吗：为何退、谁认定的？ 无 → 补触发证据。
- [ ] 有处置记录吗：数据/模型/资产各自如何处置？ 无 → 不开处置门禁。
- [ ] 有替代就绪证明吗：接替者是否已上线并经门禁？ 无 → 卡替代就绪门禁。
- [ ] 有注销确认吗：全依赖已解除？ 无 → 户籍悬挂，记为判定债务。

可判定性遵循 LGD 判定论：每道门禁应有形式化程度 ≥ L1 的判据（清单或规则），输出四态；任一要素缺失时显式"悬置"，不默默放行。

**微型示例**：某金融风控模型决定下线。触发依据 = 新模型性能更优且旧模型性能衰减；处置记录 = 权重归档至冷存储、训练数据按留存期限销毁、下游 3 个调用方已切换；迁移记录 = 调用方切换清单与回滚预案；关机事件 = 指定时点停止服务；批准门禁 = 风险官签字；替代就绪门禁 = 新模型已过变更门禁；注销确认门禁 = 旧模型户籍置"已退役"。五道门禁全过，退役闭环。

---


**（六）退役成熟度分级（L0–L3）**
- **L0 声明态**：宣称"会退"，无登记无证据——不可判定。
- **L1 清单态**：有注销清单、有处置记录，人工核对——可判定。
- **L2 规则态**：状态机与五道门禁可自动校验——半自动。
- **L3 代码态**：注销由代码强制，未过门禁不得静默下线——机器执行。
Terminance 要求强监管域（MED/ENE）达 L2/L3，软件与 AI 域至少 L1。


## 5. 跨域适用性

Terminance 是五个角度中**最先可全域落地**的一个，因为其母版在多个强监管行业早已存在，只需被显式识别为"退役治理事件"并补上三律闭环。13 域映射如下：

| 域（TID） | 最先落地的母版参照 | LGD 平移 |
|---|---|---|
| 医疗器械 MED | 注册证注销 / 召回制度、唯一器械标识（UDI）生命周期 | 器械退役门禁 = LGD-III 实例 |
| 能源电力 ENE | 风光退役纳入生态环境法典；退役叶片/组件处置规范 | 设施退役的"有门禁"范式 |
| 工业智能 IND | 产线/机组关停的资产与环保处置要求 | 资产退役"有籍→有证"闭环 |
| 数据要素 DAT | 数据销毁与留存期限制度 | 退役证据链的数据侧 |
| 加密资产 CRYPT | 链上资产冻结/回收的处置规则 | 数字资产注销门禁 |
| 自动驾驶 AUT | 自动驾驶系统下线后的模型与数据处置 | AI 退役"有证"骨架 |
| 低空经济 UAS | 飞行器/无人机退役的适航与资产处置 | 载具退役登记 |
| 机器人 ROB | 具身设备报废的资产与数据安全处置 | 物理资产退役 |
| 金融 FIN | 模型退役的变更与证据要求 | 金融模型注销 |
| 法律 LAW | 电子证据归档期满后的销毁留痕 | 证据退役门禁 |
| 政务 GOV | 政务系统下线的数据迁移与处置 | 公共资产退役 |
| 生物基因 BIO | 生物样本/基因数据销毁的合规留痕 | 敏感资产退役 |
| 教育 EDU | 教育智能体下线后的学习者数据处置 | 用户数据退役 |

最先落地的域是 **MED（医疗器械）与 ENE（能源电力）**：前者已有注册注销与 UDI 制度，后者已有生态环境法典下的退役规范，两者都只需把"退役"从被动合规补成主动治理事件，即可直接挂载 LGD 三律。映射方法统一为——取该域既有的退役/处置规制作为母版，按其环节填充"注销登记/证据链/五道门禁"三栏，缺口处显式标注"暂无执行器"，不冒充全覆盖。值得注意的是，高风险的核设施与卫星退役虽然不在 13 域主表，但其"门禁强度"可作为回灌基准，拉高通用退役门禁的下限。

## 6. 边界与不适用范围

Terminance 明确**不解决**以下事项：

- **不解决"该不该造"**：退役只管终段，准入与持续运营归 LGD 其他环节与其他域理论。
- **不解决技术删除的实现细节**：如何安全擦除存储介质、如何保证模型权重不可逆销毁，是工程与密码学问题，本角度只规定"须留处置证据"与"须过处置门禁"。
- **不提供具体法规文本**：各域退役程序以当地法规与主管部门规定为准；本角度是治理元结构，不是合规手册。
- **不主张对"退役"概念的首创权**：描述性英文术语空间已被既有文献占据，本角度仅贡献其跨域同构的三律结构。
- **不覆盖"从未登记之物"**：一个从未准入立籍的系统，退役时无户籍可注销，应先回到 LGD-I 补登记，Terminance 只对已登记对象生效。
- **不声称已被任何标准或监管采用**：外部引用与采纳目前为零；本角度为民间理论发布物，非监管意见、非法律意见。
