# BTSK 双时态知识库 v1.0（发布版）

> **一句话主张**：审计要回答的从来不是"现在知道什么"，而是"**当时知道什么**"——知识的双时间轴（有效时间 × 事务时间）是 AI 结论成为证据的前提条件。
>
> **对齐**：LGD-II「有证」（证据工件的知识层地基）· 数据工程双时态模型（SQL:2011 bitemporal）· 关系数据库时代已验证的工程传统。

## 一、问题：AI 的知识是"单时态"的，所以不可审计

一个 AI 系统依据知识库作出了一个决定。三个月后审计员问：**它当时依据的是什么？**

主流 RAG/知识库实现无法回答：

1. **知识被原地改写**——旧版本覆盖删除，"当时的知识状态"不可重建；
2. **修正不区分时间**——一条事实从"错误"改成"正确"，历史里看起来它"一直正确"；
3. **录入时间不可考**——无法区分"当时已知但被忽略"与"事后才补录"。

这在人类组织里是不可接受的：财务有账簿不可涂改、病历有病程记录只增不删、法律有档案法。**单时态知识库让 AI 组织回到了"没有账簿"的时代。**

## 二、双时间轴定义

| 轴 | 定义 | 回答的问题 | 治理用途 |
|---|---|---|---|
| **有效时间 Valid time** | 这条知识在现实世界何时为真 | "当时世界是什么样？" | 回放决策时刻的世界状态 |
| **事务时间 Transaction time** | 我们何时知道/录入/修正了它 | "我们何时知道的？" | 审计知识自身演化，识破事后改口 |

两轴正交，任何知识条目可回答四问：现在有效吗 / 当时有效吗 / 何时录入 / 何时修正。

**推论（证据资格条件）**：AI 结论引用的知识若不可回溯到"决策时刻的版本"，该结论**不具备审计证据资格**——不是质量差，是证据资格缺失。

## 三、治理规矩（BTSK 的差异化贡献）

双时态数据模型本身在数据库领域是成熟工程（SQL:2011 标准化）。**BTSK 的贡献不在数据模型，而在把双时态变成 AI 治理的规矩层**：

1. **证据资格门槛**：LGD-II 六类证据工件中，凡引用知识库的，必须满足双时态可回溯——否则证据无效。
2. **修改即过闸**：改知识 = 知识的"演化"，须过 LGD-III 门禁；且**历史可查不可抹**（修正=追加新版本+指向旧版本，而非覆盖）。
3. **责任链绑定**：每条知识的写入/修正者（人还是哪个 agent、经谁授权）随事务时间记录——知识责任链末端仍是自然人。
4. **回放协议**：给定决策时刻 T，任何人可重建"T 时刻的知识快照"——审计可复现。

## 四、2026 前沿对照（2026-09-08）

- **Zep / Graphiti** 已将双时态数据模型工程化于 agent 记忆层（biotemporal knowledge graph：事件双时态 + 实体有效性区间）——这是对 BTSK 主张的**工程呼应**，印证双时态正在成为 agent 记忆的公认需求。
- **BTSK vs Graphiti 定位差**：Graphiti 解决"记 what/when 的工程效率"；BTSK 解决"知识作为**证据**的资格规矩"——双时态知识引用具备审计证据资格的条件、修改门禁语义、与 LGD-II 证据工件的绑定规范。**工程呼应印证需求，治理规矩层仍是空白。**
- arXiv 2508.03095 / 2604.23280 综述确认 agent 证据与治理层为开放问题——BTSK 与 LGD-II 构成该空白的知识层答案。

## 五、落地实况（MedXpert-RA）

- 双机同步（sync_scan / evolve_scan）保持双时态一致；
- 知识条目版本化：修正=追加新版本+指回旧版本；
- 与确权体系联动：作品指纹登记册（SHA-256+时间戳）即 BTSK 思想在 IP 保护上的应用实例。

## 六、诚实边界

- BTSK 是治理规矩框架，不提供具体存储引擎实现；工程选型（SQL bitemporal 表 / biotemporal graph / 事件溯源）由落地者决定。
- "证据资格条件"是 LGD 体系内的规矩（民间框架），不具法律强制力；司法场景的证据规则以属地法律为准。
- 双时态覆盖"知识的真伪演化"，不覆盖感知输入的真实性（那是数据卡/来源验证的问题）。
