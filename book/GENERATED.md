# 关于 `book/` 目录（生成物说明）

本目录下的文件是**生成物**（build artifacts），不是源文件。
请勿直接编辑本目录中的 `.html` / `.epub` —— 改了会被下次重建覆盖，而且会让产物与源分叉。

---

## 1. 源在哪里

| 角色 | 位置 |
|---|---|
| **署名/版权/版本/DOI/仓库地址的单一真值源** | [`_meta/source.toml`](../_meta/source.toml) |
| **章节正文**（这本书的正文来源） | [`docs/`](../docs/) 下的 17 篇 markdown |
| **构建脚本** | 由维护者本地持有（参数：输出目录 / 文库版本号） |
| 徽章与视觉资源 | [`badge/`](../badge/) |

## 2. 重建步骤

```
# 1) 改口径 → 只改 _meta/source.toml（不要改产物）
# 2) 校验所有承载位与真值源一致
python _tools/sync_meta.py --check <repo>
# 3) 由源重建产物（须使用 Python-Markdown 渲染器，见 §4）
python _build_book.py --out <repo>/book --libver 1.1
# 4) 校验产物未漂移
python _tools/verify_generated.py <repo>
```

## 3. ⚠️ 已知缺口（待解决）

这是本目录唯一一处违背「产物只由构建产生」原则的地方，已登记在案。
**彻底解法**：把 v1.1 的额外章节与资源纳入构建脚本定义，使 v1.1 与其源一致可重建。

## 4. 渲染器要求

产物 HTML 由 markdown 渲染器生成。不同渲染器对表格 / 围栏代码块的输出 HTML 存在细微差异，
会导致「同一份源、不同环境重建结果不同」。因此：

- **正式重建必须使用 Python-Markdown**（`pip install markdown`）
- 若环境中缺失，脚本会回退到另一渲染器并在输出中**明确打印所用渲染器**
- 出现回退时，请视为「产物不可复现」，不要提交

## 5. 校验

提交前请跑以下两项，任一失败即不要提交：

```
python _tools/sync_meta.py --check <repo>        # 真值源派生一致性
python _tools/verify_generated.py <repo>         # 本目录产物是否偏离真值源
```

> 维护者本地另有一道更严格的「署名 / 版权 / 元数据合规」校验，因其含内部治理术语，
> 刻意不放进公开仓库；它覆盖的范围是上面两项的超集，并在推送前自动执行。
